АНАЛИТИКА NBANK — РЕЗУЛЬТАТЫ
============================
Источник: Grafana / Prometheus (метрики *_total).
Окно: последние сутки (24h). Все значения посчитаны через increase(metric[24h]),
что корректно учитывает сброс счётчиков при перезапуске пода backend
(restartCount=1), поэтому суммы за 24ч могут быть больше «сырого» значения счётчика.
Дата снятия: 2026-05-31 (время в графиках — UTC).

Примечание: вопросы «кто/какой пользователь/средняя сумма/причины ошибок»
отвечаются по логам в Kibana и здесь пока НЕ заполнены.

------------------------------------------------------------
1. Сколько новых пользователей было создано за последние сутки?
   [Grafana: sum(increase(user_created_total[24h]))]
   Ответ: ~478

2. Сколько раз пользователи входили в систему?
   [Grafana: sum(increase(user_login_total[24h]))]
   Ответ: ~979

3. Сколько раз запрашивали профиль клиента, и сколько раз он был обновлён?
   [Grafana: customer_profile_fetched_total / customer_profile_updated_total]
   Ответ: запрошен ~231 раз, обновлён ~85 раз

4. Сколько аккаунтов было создано?
   [Grafana: sum(increase(account_created_total[24h]))]
   Ответ: ~217

5. Сколько раз администратор просматривал список пользователей?
   [Grafana: sum(increase(admin_user_listed_total[24h]))]
   Ответ: ~88

6. Сколько пользователей было удалено админом?
   [Grafana: sum(increase(admin_user_deleted_total[24h]))]
   Ответ: ~466

7. Сколько переводов было начато?
   [Grafana: sum(increase(transfer_started_total[24h]))]
   Ответ: ~240

8. Сколько из них были успешными, а сколько — неуспешными?
   [Grafana: transfer_success_total / transfer_failed_total]
   Ответ: успешных ~215, неуспешных ~25 (215 + 25 = 240 = начато)

9. Какой процент успешных переводов? Какой процент неуспешных переводов?
   [Grafana: 100 * success / started ; 100 * failed / started]
   Ответ: успешных ~89.6%, неуспешных ~10.4%

10. Были ли всплески ошибок при переводах? В какое время?
    [Grafana: панель "Transfer failures (spikes)" — sum(rate(transfer_failed_total[5m]))]
    Ответ: да. Ошибки сконцентрированы в окне ~16:20–16:35 UTC (2026-05-31),
    пик около 16:28 UTC. Вне этого окна ошибок переводов практически нет.

11. Кто был самым активным пользователем по количеству логинов?
    [Kibana: message:"Login successful for user", terms по username]
    Ответ: admin — 24 логина (следующие пользователи по ~11).

12. Кто чаще всего обновлял профиль?
    [Kibana: message:"Profile updated for user", terms по username]
    Ответ: явного лидера нет — все 85 обновлений профиля распределены по
    85 разным пользователям, каждый обновлял ровно 1 раз (топ-значения
    в terms все = 1, напр. HGA9RfBrrMPi, HYEqZAUkBO, 9sCaivj и т.д.).

13. Сколько пользователей просматривали список транзакций?
    [Grafana: sum(increase(account_transactions_viewed_total[24h]))]
    Ответ: 0 (эндпоинт просмотра списка транзакций за сутки не вызывался)

14. Как изменилась активность по сравнению с предыдущими днями?
    [Grafana: increase(...[1h]) на диапазоне Last 7 days, либо offset 24h/48h]
    Ответ: сравнение невозможно — данных за предыдущие сутки нет
    (offset 24h/48h = no data). Вся активность укладывается в одно окно
    последних суток (стенд поднят недавно). За предыдущие дни активность = 0.

15. Каков процент успешных транзакций за сутки?
    [Grafana: 100 * transfer_success / transfer_started за 24h]
    Ответ: ~89.6%

16. Кто был самым активным пользователем? Какая средняя сумма перевода за сутки?
    Какие причины ошибок встречаются чаще всего?
    Ответ:
        - самый активный пользователь (по всем событиям) -> admin (48 событий)
        - средняя сумма перевода за сутки -> 3,865.526
          (среднее по 20 строкам "Transfer successful"; для справки среднее
           по всем 50 инициированным переводам "Transfer request" = 4,080.27)
        - причины ошибок (по убыванию частоты) ->
            * Invalid name format from user: 70
            * Transfer failed (insufficient funds / invalid accounts): 16
            * Unauthorized transfer access by: 10

17. Какие пользователи чаще всего сталкивались с ошибками при переводах?
    [Kibana: message:"Unauthorized transfer access by", terms по username]
    Важно: строки "Transfer failed" логируют только ID счетов (from/to),
    без имени пользователя — по ним привязать ошибку к юзеру нельзя.
    Имя пользователя есть только в строках "Unauthorized transfer access by 'X'"
    (это аутентифицированный пользователь, пытающийся перевести с чужого счёта;
    запрос без авторизации, напр. test_account_transfer_no_auth, даёт 401 на
    фильтре Spring Security и в лог бизнес-строку НЕ пишет).
    Ответ: явного "рекордсмена" нет — 10 попыток неавторизованного перевода
    распределены по 10 разным пользователям, по 1 разу каждый.

18. Были ли случаи, когда создание пользователя падало более 3 раз подряд?
    [Kibana: error.message:* or message:"Exception", гистограмма по времени]
    Ответ: нет.

19. Сопоставьте метрики и логи: есть ли рост, который не отражён в логах?
    [Grafana: sum(user_login_total) ; Kibana: count "Login successful for user"]
    Ответ: при сравнении одного и того же события за период значения расходятся:
        - Grafana, сырой счётчик sum(user_login_total) ≈ 885 (считает с момента
          последнего рестарта пода backend, restartCount=1);
        - Kibana, число строк "Login successful for user" ≈ 979 (логи сохраняются
          между перезапусками).
    Расхождение объясняется СБРОСОМ счётчика Prometheus при рестарте: сырое
    значение меньше числа строк в логах. При reset-safe подсчёте
    increase(user_login_total[24h]) ≈ 979 — совпадает с логами. Вывод: «рост»,
    не отражённый 1:1 в сыром счётчике, — это артефакт сброса; логи остаются
    источником истины по фактическим событиям.
